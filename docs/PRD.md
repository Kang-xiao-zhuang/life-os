# LifeOS

> **Personal Operating System**
>
> 一个本地优先（Local First）的 Android 个人工作台。

LifeOS 不是 Todo 软件，不是笔记软件，也不是日历软件。

它是一个帮助我管理工作、学习、项目、习惯和成长的人生操作系统。

------

# 产品目标

开发一款**仅供个人使用**的 Android App。

设计理念：

- Local First（所有数据保存在本地）
- Offline First（无网络也能完整使用）
- No Login（无需账号）
- Privacy First（所有数据属于用户）
- Fast（启动快、操作简单）
- Minimal（界面简洁）
- Export Friendly（支持完整导入导出）

目前不考虑：

- 云同步
- 多人协作
- AI 功能
- 在线账号系统

未来如有需要，再作为独立模块增加。

------

# 技术栈

- React Native
- TypeScript
- React Navigation
- Zustand（状态管理）
- SQLite（数据存储）
- React Native MMKV（配置缓存）

架构：

```text
UI
 ↓
Service
 ↓
Repository
 ↓
SQLite
```

业务层不得直接操作数据库。

------

# V1 功能

## 🏠 Dashboard（首页）

首页展示今天最重要的信息：

- 今日最重要任务（MIT）
- 今日任务
- 今日习惯
- 快速记录入口
- 今日复盘入口

Dashboard 是整个 App 最重要、使用频率最高的页面。

------

## 📁 Projects（项目）

用于管理长期项目。

例如：

- 工作
- 学习
- 阅读
- 健身
- 自媒体

每个 Project 可以拥有多个 Task。

------

## ✅ Tasks（任务）

支持：

- 创建
- 编辑
- 删除
- 完成
- 截止日期
- 所属 Project

保持简单，不开发复杂筛选。

------

## ➕ Capture（快速记录）

一键记录任何灵感。

例如：

- 一个待办
- 一个想法
- 一句话
- 一个创意

以后再整理分类。

------

## 🔥 Habits（习惯）

用于记录每天坚持的事情。

支持：

- 创建习惯
- 编辑习惯
- 删除习惯
- 每日打卡
- 查看连续打卡天数（Streak）
- 查看本周完成情况

例如：

- 📚 阅读
- 🏋 健身
- ✍ 写作
- 🎥 内容创作
- 🇬🇧 英语学习

V1 不需要复杂统计。

------

## 📖 Journal（每日复盘）

每天一篇。

包含：

- 今天完成了什么
- 今天最大的收获
- 今天遇到的问题
- 明天最重要的一件事

支持 Markdown。

------

## ⚙️ Settings（设置）

包含：

- 深色模式
- 导出数据
- 导入数据
- 关于

Settings 不放到底部导航，而是放在 Dashboard 右上角。

------

# 底部导航

```
🏠 Dashboard

📁 Projects

➕ Capture

✅ Habits

📖 Journal
```

Capture 放在中间，方便快速记录。

------

# 数据存储

所有数据仅保存在本地 SQLite。

附件和图片保存在 App 私有目录。

支持完整备份：

```
LifeOS_Backup.zip

database.db
attachments/
config.json
```

支持一键恢复全部数据。

# UI 风格

关键词：

- Calm
- Minimal
- Modern
- Clean

设计原则：

- 深色模式优先
- 卡片式布局
- 留白充足
- 柔和圆角
- 动画简洁自然
- 不增加无意义的视觉效果

------

# 开发原则

所有功能必须遵守：

1. 保持界面简单
2. 优先保证流畅体验
3. 不增加无意义配置
4. 不引入复杂依赖
5. 保持代码可维护
6. 一个模块只负责一件事情
7. 优先完成 MVP，再持续迭代

------

# Claude Code 开发要求

开发过程中请遵守以下规范：

- 保持统一的目录结构。
- 保持统一的命名规范。
- 每完成一个模块，都确保可以正常运行后再继续开发。
- 不提前开发未来版本功能。
- 优先采用简单、稳定、易维护的实现方式。
- 代码应具备良好的可读性，并添加必要注释。

# 最终目标

LifeOS 的目标不是成为功能最多的效率工具。

而是成为我每天都会打开、长期陪伴我的个人工作台。

每新增一个功能，都必须回答一个问题：

> **它是否值得每天使用？**

如果答案是否定的，就不要加入。

当设计方案存在多个可选实现时，请优先选择简单、稳定、可维护的方案，而不是最复杂或最炫的方案。始终以长期维护和个人使用体验为第一优先级。
